# 보고서 작성 기준

지적이 반복되는 것은 기준이 없었기 때문이다. 여기에 기준을 적고,
`app/frontend/scripts/report-quality-rubric.mjs` 가 그 기준을 기계적으로 채점한다.
새 결함을 발견하면 **먼저 이 문서에 기준을 추가하고, 채점 항목을 만든 뒤** 고친다.

## 1. 읽는 사람이 해석을 떠안지 않는다
- 숫자·점수·단계를 적었으면 같은 문장 안에서 "그래서 무슨 뜻인지"까지 쓴다.
- 점수를 적으면 눈금(몇 점이 본전인지)을 함께 밝힌다.
- 내재가치는 반드시 시가총액과 견주어 싼지 비싼지를 말한다.

## 2. 기계의 말을 쓰지 않는다
- 원시 필드명 금지: `key_risk_ko`, `growth_analysis`, `base_fcff`, `life_cycle.playbook`.
  점(.)으로 이어진 경로도 한 덩어리로 옮긴다.
- 판정값 영어 금지: `bearish`, `low`, `high`, `insufficient`.
- 데이터 메타 금지: `(period: TTM, report period: …)`.
- 마커·강조 기호 금지: `[#+]`, `[!`, `**`.
- 약어는 한국어로: `2H`→하반기, `1H`→상반기, `YoY`→전년 대비, `QoQ`→전분기 대비.

## 3. 문장은 끝맺고, 제목은 완결한다
- 연결어미(`~지만`, `~는데`)로 문장이나 제목을 끝내지 않는다.
- 제목이 여는 괄호·기호로 끝나지 않는다(`핵심 판단 - [`).
- 모든 카드는 제목을 갖는다. 규칙으로 못 뽑으면 앞머리를 잘라 만든다.
- 종결부호 뒤에 숫자가 오면 문장 끝이 아니다(`206.1`을 `206.`+`1`로 자르지 않는다).
- 마침표 뒤에 곧바로 한글이 붙으면 문장 경계다. 띄우고 줄을 바꾼다.

## 4. 줄바꿈은 눈이 따라갈 수 있게
- 한 문단은 260자를 넘지 않는다. 넘으면 문장→절 순서로 나눈다.
- 문단 안의 번호 목록(`(1)`, `1.`, `2.`)은 각각 줄을 바꾼다.
- 예외: 인용문이 문단의 40%를 넘으면 쪼개지 않는다. 인용 안에서 끊으면 원문이 깨진다.

## 5. 같은 말을 되풀이하지 않는다
- 한 주제(선행PER↔TTM, DCF↔시장가)의 주장은 보고서에서 한 번만.
  결론(01)은 요약이므로 예외 — 결론이 말했으면 본문에서 반복하지 않는다.
- 같은 카드·같은 제목이 두 번 나오지 않는다.

## 6. 원문은 살리고 번역을 붙인다
- 영어 인용문은 고치지 않는다. 원문이 근거다.
- 영어 인용 바로 다음 줄에 괄호로 한국어 번역을 붙인다.
- 인용부호 안의 영어는 '남은 영어'로 세지 않는다.

## 7. 독자에게 숙제를 남기지 않는다
- "확인 필요", "체크리스트", "위치를 확인" 같은 지시는 근거 카드가 아니다.
- 원문은 출처 섹션의 '공시 원문 펼쳐보기'로 확인한다.
